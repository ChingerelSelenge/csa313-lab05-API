### Давхар алдааны ажиглалт (TC06, TC07)
 
Заавар нэг хүсэлтэд хэд хэдэн алдаа зэрэг байвал аль нь буцахыг бичээгүй тул сервер дээр бодитоор туршиж тогтоосон:
 
- Оюутан ч, хичээл ч байхгүй (`NOBODY` / `NOCOURSE`) үед `200 ERROR_NO_STUDENT` буцсан.
- Идэвхгүй оюутан + байхгүй хичээл (`INACT1` / `NOCOURSE`) үед `200 ERROR_INACTIVE_STUDENT` буцсан.
Эндээс сервер оюутны шалгалтыг (байгаа эсэх, идэвхтэй эсэх) хичээлийн шалгалтаас өмнө хийдэг нь харагдаж байна. Энэ дарааллыг тест бүрд нэг тодорхой утгаар (`eql`) тогтмол бичсэн, хоёр утгын аль нэгийг зөвшөөрдөг сул oracle хийгээгүй. TC06 нь үүсгэх өгөгдөлгүй кейс тул setup PUT хийгээгүй (хоёр ID зориуд байхгүй байх ёстой).

## Даалгавар 3 — Collection
 
`lab05-collection.json` нь TC01–TC12 тус бүрт тусдаа folder-тэй, нийт 30 request агуулна. Folder бүр өөрийн `PUT` setup-аа (оюутан, хичээл) өөрөө хийж, дараа нь `POST /registrations` хийнэ, тиймээс тестүүд хоорондоо хамааралгүй бөгөөд ажиллуулах дараалал нөлөөлөхгүй. `registrationID`-ийн яг утгыг шалгаагүй (сервер санах ойд хуримтлуулдаг тул), зөвхөн тоо мөн эсэхийг шалгасан. `baseUrl`-ийг collection variable-д (`http://localhost:3000`) тавьсан. 12 кейс нь 12 assertion гэсэн үг биш: нэг кейст статус, `result`, `missing` зэрэг хэд хэдэн `pm.test` байна.

## Дүгнэлт
 
Тест дизайны 5 алхмаас хамгийн их бодол шаардсан нь сонголтуудыг эквивалент ангид хуваах, боломжгүй хослолыг тодорхойлох хоёр дахь, гурав дахь алхам байлаа. Оюутан байхгүй үед түүний төлөв, үзсэн хичээлийг тодорхойлох боломжгүй, хичээл байхгүй үед урьдач нөхцөл утгагүй болдог нь боломжгүй хослол болж таарсан. Заавар давхар алдааны үед аль алдаа буцахыг бичээгүй тул TC06, TC07-г сервер дээр бодитоор туршиж тогтоосон. Үр дүнд сервер оюутны шалгалтыг (байгаа эсэх, идэвхтэй эсэх) хичээлийн шалгалтаас өмнө хийдэг нь тодорхой болсон. Энэ дарааллыг oracle-д нэг тодорхой утгаар бичсэн, учир нь хоёр утгыг зөвшөөрдөг oracle хоёр алдааны аль нь ч буцсаныг баталж чадахгүй. Тест бүр өөрийн PUT setup-тай тул ажиллуулах дараалал, сервер дахин асаасан эсэхээс үл хамаарна, мөн `registrationID`-ийн яг утгыг шалгаагүй нь сервер санах ойд хуримтлуулдаг онцлогт тохирсон. 12 кейс нь 29 assertion болсон нь нэг кейст статус, `result`, `missing` гэсэн хэд хэдэн шалгалт байдагтай холбоотой. PASS ажиллуулалтад бүх 29 assertion давж `exit=0` гарсан тул 12 спецификацид сервер хүлээлттэй нийцэж байгаа бөгөөд спецификацийн хувьд согог илрээгүй. Харин нэг оюутныг нэг хичээлд давхар бүртгэх, ер бусын ID зэрэг тохиолдлыг би тестлээгүй тул тэдгээрт согог байж болзошгүй. FAIL туршилт зориуд буруу oracle-ийг Newman илрүүлж `exit=1` буцаадгийг, DOWN туршилт сервер унтарсан үед `ECONNREFUSED` гарч мөн `exit=1` буцаадгийг харуулсан. Хоёулаа `exit=1` тул exit code-оос ялгах боломжгүй, гаралтын текстээс интерфейсийн алдааг oracle-ийн алдаанаас ялгах хэрэгтэй гэдгийг ойлгосон.
